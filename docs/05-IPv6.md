# IPv6 Addressing, CIDR, and Routing

This repository now includes a portable IPv6 learning module alongside the IPv4 and VLSM exercises.

## Address model

IPv6 addresses are 128 bits. The implementation stores the address as 16 octets in `IPv6Address` rather than relying on compiler-specific 128-bit integer types. This keeps the code portable across GCC, Clang, and MSVC.

```cpp
struct IPv6Address {
  std::array<std::uint8_t, 16> bytes{};
};
```

## Parsing and formatting

`parse_ipv6()` accepts:

- Full eight-hextet notation, such as `2001:0db8:0000:0000:0000:0000:0000:0042`.
- Zero-compressed notation, such as `2001:db8::42`.
- IPv4-mapped notation, such as `::ffff:192.0.2.1`.

`format_ipv6()` emits lowercase hexadecimal and compresses the longest zero run of at least two hextets, following the normal RFC 5952 presentation rules used for this learning tool.

## IPv6 CIDR

An IPv6 CIDR prefix has a length from `/0` through `/128`.

For a prefix length `p`, the first `p` bits identify the network prefix. The remaining `128-p` bits identify addresses within that prefix.

Examples:

| Prefix | Meaning |
| --- | --- |
| `/0` | Entire IPv6 address space |
| `/32` | Common site/provider allocation boundary |
| `/48` | Common routed site prefix |
| `/64` | Common LAN/interface subnet boundary |
| `/128` | One individual address |

`make_ipv6_cidr()` returns both the aligned network address and the last address in the prefix.

## Longest-prefix match

`ipv6_lpm_lookup()` applies the same routing principle used by IPv4:

1. Check which routes contain the destination.
2. Select the route with the longest prefix.
3. If two routes have the same prefix length, select the lower metric.
4. Return `-1` when no route matches.

The implementation is intentionally simple and educational. Production routers use optimized forwarding tables such as Patricia tries, radix trees, or hardware TCAM rather than scanning every route.

## Lab

Build and run `ipv6-cidr` after configuring the project with CMake. The lab demonstrates:

- IPv6 parsing.
- `/64` network calculation.
- Last-address calculation.
- Prefix membership testing.
- IPv6 longest-prefix-match routing.

## Scope and limitations

This is a CCNA-oriented addressing and routing toolkit, not a complete IPv6 protocol stack. It does not implement Neighbor Discovery, SLAAC, DHCPv6, ICMPv6, extension-header processing, packet forwarding, or a real network interface.
